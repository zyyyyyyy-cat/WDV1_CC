# WHU/UAD 训练轨迹日志分析：早期领先、中期被反超、后期追不上的原因

**分析范围**：WHU-MARS-1000，AS-ReID，Overall ALL→ALL，256×128；DDP 4 卡（world=4，全局 batch 256，LR 0.032）与 single（batch 64，LR 0.008）分别对齐。训练配置 120 epoch；HiHR Stage2 为 60 epoch（另有 60 epoch Stage1）。

**核心结论（先给答案）**：

1. **只有 TAUR v2 完整体现“早期领先 → 中期被反超 → 末期落后”**：ep10 相对 H014 为 +1.44 mAP/+4.81 R1，ep90 mAP 首次转负，ep120 为 −0.45/−0.31。PAT E1a DDP 与 ViSA 是“早期 mAP/R1 领先 → 末期 R1 落后（mAP 持平或小升）”；HiHR Stage2 的早期领先主要是 Stage1 已训练 60 epoch 的预算优势；按同总预算对齐后，Stage2 起点（总70）即落后，最终 R1 也落后。SCSR V3/V4.1 基本持平；SFTC、ICRE、M-SpecGene、RLE 从 ep10 就落后，并未追上。
2. **日志中没有“后期绝对下降”**：所有对比实验最后 30 epoch 的 mAP、R1 绝对斜率仍为正（约 +0.0015～+0.0395 pp/epoch）。所谓“后期下降”是相对差距：基线 H014 在 90→120 仍提升 mAP +0.29、R1 +0.97（尾段 R1 斜率 +0.033 pp/epoch）；TAUR/PAT/HiHR 的 ΔR1 尾段斜率为负，ViSA 的 R1 在基线附近震荡、末期略低。
3. **主因不是训练损失发散**：除 M-SpecGene 早期 PCA 从 0 恢复、PAT 无 CE 外，各实验 CE/WRT/GPD 在采样区间总体下降；30–90 epoch 没有出现 CE 上升、PCA/GPD 突然崩塌或 WRT 异常震荡。日志不支持“后期过拟合导致验证指标下降”的直觉解释；更支持“早期快速拟合/预算优势 + 训练-测试几何不一致 + 共同训练代价 + 后期相对饱和”。
4. **机制上最硬的三条证据**：(a) TAUR 的排序 loss 对 Adapter 的梯度仅为 UAD loss 的 0.04%→1.8%，且 Adapter 残差被 rho=0.1 限制；(b) PAT E1a 的 CSL 全程记录为 0.000，且 PSD 替换了全局 ID CE，Part Token 与 CLS 在注意力 mask 中断开、测试只用 CLS；(c) ViSA 的融合 WRT 对 global 分支 detach，但测试距离固定包含 20% local 分量。三者都直接对应“训练目标与测试几何不一致”，与 R1 后期落后一致。

> 证据标注：**[日志事实]** 为日志直接读取；**[实现事实]** 为当前本地代码静态读取；**[实验支持]** 为轨迹/指标与机制一致；**[机制假设]** 为需要权重、梯度或额外对照才能确认的解释。指标单位为 %，差值为 pp。

## 1. 解析方法与证据边界

- **验证块**：日志中 `Validation Results - Epoch: N` 后紧跟 `mAP`、`Rank-1/5/10`。实际是对测试集每 10 epoch 的评测，不是独立验证集；正式结果取第 120 epoch（HiHR Stage2 第 60 epoch）的最后一个完整块，与 `05_Results.csv` 一致。
- **轨迹提取**：每 10 epoch 一个点；epoch 10–120（或 10–60）。损失取该 epoch 内所有 `Epoch[N] a, b, c, d` 行的均值；UAD 四元组顺序为 **CE, WRT, PCA, GPD**（`processor.py:195-217` 的 meter 顺序），PCA 原始 loss 还乘以 `PCA_LOSS_WEIGHT=0.01`，GPD 权重为 1、tau=0.03、原型 EMA momentum=0.2（`configs/UAD.yml:11-13`）。
- **PAT 例外**：H032 的日志不是四元组，而是 `global_metric, global_proca, gpd, csl, psd`。其中 `global_metric` 是 WRT，`global_proca` 是 PCA，`gpd` 是 GPD，`csl` 全程 0.000，`psd` 是替换全局 ID CE 的软标签目标（PSD_LAMBDA=0.5，内部为 0.5 soft + 0.5 hard CE）。因此 CSV 中 H032 的 `ce` 留空，`wrt=global_metric`、`pca=global_proca`、`gpd=gpd`；PSD/CSL 在报告中单列。
- **模式**：DDP 与 single 不混用；DDP 对齐 H014，single 对齐 H019。H001/H003 的 Stage2 与 H014 同为 DDP，但其 Stage1 另有 60 epoch，严格同轮对比会在第 4 节同时给出“同 Stage2 轮次”和“同总训练预算”两套表。
- **日志来源**：历史原目录多数已不在本地（HiHR、ICRE、KGL、PAT、RLE、M-SpecGene 等），本次使用 2026-10-24 审计镜像 `MIRROR`；SCSR/SFTC/TAUR/ViSA 优先用本地 `LOCAL` 原日志，并已核对与镜像 md5 相同（H014 主日志与镜像也相同：`041d93f8…`）。路径前缀：`MIRROR:` = `D:/CODE/Doing/WHU_Code/WHU_Research_Archive/2026-10-24_Historical_Audit/_audit_evidence/WHU_base`；`LOCAL:` = `D:/CODE/Doing/WHU_base`；`MAIN:` = `D:/CODE/Doing/WHU_Code/WHU`；`MIRROR_CODE:` = `.../_audit_evidence/WHU_Code`。
- **未做**：未加载权重、未重跑推理、未读取原型库/梯度张量、未做逐模态轨迹；单 seed 为主，不能把小幅差值当因果。

## 7. 关键发现（按证据强度）

### 7.1 现象分类：不是所有方法都符合题设

### 7.2 为什么“早期好、后期差”

**发现 1：基线的后期 R1 仍在加速，而方法提前饱和。**  [日志事实] H014 在 90→120 的 mAP +0.29、R1 +0.97；尾段 R1 斜率 +0.0325 pp/epoch。TAUR 的 R1 尾段绝对斜率仅 +0.0025、PAT +0.0170、HiHR Stage2 +0.0200，均明显低于基线 +0.0325；ViSA 的 R1 尾段 +0.0390，但轨迹在基线附近震荡（ep100/120 低于基线），ΔR1 斜率 +0.0065 只是噪声级。绝对指标没有下降，是**基线追上来**。

**发现 2：早期优势主要来自“更快拟合”，不是“更好的最终几何”。**  [日志事实] HiHR Stage2 ep10 的 CE 已降到 0.45（Stage1 初始化），TAUR ep10 CE 1.38、PAT ep10 PSD 2.70、ViSA ep10 CE 2.11；这些方法在 ep10–20 的 mAP/R1 领先最大，但后期增益迅速变小。相反，基线 CE 从 2.15 持续降到 0.11、GPD 从 1.64 降到 0.08，后段仍在改善。**“先到”不等于“到得更高”。**

**发现 3：TAUR 的排序监督对 Adapter 的梯度贡献极小。**  [日志事实] 日志 `TAUR mean Adapter gradient contribution` 显示 `rank_to_uad_ratio` 在 ep5 为 0.0004、ep20 为 0.0088、ep60 为 0.0135、ep120 为 0.0157，即排序 loss 只占 UAD loss 对 Adapter 梯度的 0.04%–1.6%；余弦 0.21–0.50。 [实现事实] Adapter 残差被 `rho=0.10` 限制（`thermal_adapter.py:8-34`），且排序梯度只回 Adapter（`processor.py:260-282`）。 [实验支持] TAUR 的领先在 ep20 后持续缩小、ep90 mAP 转负，与“Adapter 早期快速适配后饱和、排序信号不足以持续重塑全局几何”一致。**[机制假设]** 需要 ON/OFF 或增大 rank 权重的对照才能确认因果。

**发现 4：PAT 的 Part 监督与测试几何不一致，且 CSL 实际未工作。**  [日志事实] H032 的 `csl` 在所有 240 条损失行中为 0.000/−0.000；PSD 从 2.697 降到 0.219；`PSD_REPLACE_ID_CE: True`（日志第 72 行），即全局 ID CE 被 PSD 替换。 [实现事实] `part_attention_mask` 让 CLS+Patches 只能互相注意、Part Token 只注意本区域 Patches（`vit_pytorch.py:333-348`）；推理 `forward_features` 只返回 `x[:,0]`（CLS）。 [实验支持] PAT 的 mAP 后期仍小升、R1 从 ep70 起落后，末期 +0.02/−0.92，符合“局部/软标签目标改善正样本覆盖，但不改善首位精确竞争”。**[机制假设]** PSD 软目标是否直接扁平化 top-1 排序，需要 logits/邻居质量分析。

**发现 5：ViSA 的训练融合 WRT 对 global 分支 detach，但测试距离固定包含 20% local。**  [实现事实] `make_retrieval_feature(..., detach_global_for_loss=True)`（`processor.py:247`）；融合为 `[normalize(shared), 0.5*normalize(local)]/sqrt(1.25)`（`visa_adapt.py:149-154`），local 平方范数占 20%；local 的 patch 值和图邻接均 detach（`visa_adapt.py:79-80,102-103`）。 [日志事实] ViSA ep20 达峰 +0.76/+1.33，ep100/120 转为 mAP+/R1−，末期 +0.28/−0.34。 [实验支持] 这与“local 分量提升 mAP（更多正样本被覆盖），但固定 20% 距离贡献损害 R1”一致。**[机制假设]** 需要 local-only / fusion-only 的检索分解才能定量归因。

**发现 6：HiHR 的 Stage1→Stage2 切换本身造成一次几何破坏。**  [日志事实] Stage1 终点 10.72/27.99；Stage2 ep10（总 70）降到 9.83/26.76，随后 mAP 在总 90 才超过基线、R1 一直落后。 [实现事实] Stage2 加载 `INIT_CHECKPOINT=.../HiHR_H2_stage1/transformer_60.pth`（日志第 2、26 行），新增 Parent/Child 查询读出、1792 维描述子与分类器。 [实验支持] HHL 开启/关闭（H003/H001）轨迹几乎相同，排除“HHL 未执行”；差异来自 Stage2 结构与两段优化。**[机制假设]** 新描述子/分类器的初始化与 WRT 尺度重标定可能对 Stage1 的 CLS 几何产生短期冲击。

**发现 7：SFTC/ICRE 的失败更像共同训练代价/优化干扰，而非后期过拟合。**  [日志事实] SFTC ep10 CE 2.64（基线 2.15）、ICRE 2.41；两者后期 CE 仍降到 0.13/0.11，但指标差距在中期扩大（ICRE mAP 差从 ep10 −0.81 到 ep50 −2.74；SFTC ep20 后稳定在 −0.9～−1.2）。 [实现事实] SFTC 把 local K/V 与原 K/V 放进同一个 softmax 竞争（`vit_pytorch.py:129-133`）；ICRE 把跨层增强结果以 `gamma` 残差写回 L9（`clee.py:41-68`）。 [实验支持] “损失继续下降但指标不升”支持表示路径被改写/竞争，而非优化没收敛。**[机制假设]** 具体是 softmax 竞争、背景噪声还是 WD 造成，日志不能区分。

**发现 8：RLE 是输入增强导致的欠拟合，不是后期退化。**  [日志事实] ep10 四项损失全面高于基线（CE 3.58–3.75 vs 3.07，GPD 2.75–3.08 vs 2.09）；到 ep120 仍高（CE 0.56–0.69 vs 0.37，GPD 0.42–0.54 vs 0.26）。 [实现事实] RLE 在 Normalize 前对 RGB/NIR/TIR 做 MRLE/RRLE（`datasets/rle.py:12-107`），E2 关闭 TIR 仍显著下降。 [实验支持] 四个版本轨迹几乎重合、差距随训练缓慢缩小，符合“增强过强→固定 120 epoch 内欠拟合”，而不是“后期过拟合”。

**发现 9：M-SpecGene 是初始化/收敛失败，而非“被反超”。**  [日志事实] ep1 CE=6.214≈ln500、PCA=0.003、GPD=5.36；ep10 CE=4.28、PCA=0.000、GPD=6.192≈ln500；ep120 CE 仍 1.37、GPD 1.03，mAP/R1 仅 5.23/14.79。 [实现事实] 配置 `PRETRAIN_PATH=./pretrained/M-SpecGene_VIT-B_UAD_256x128.pth`（日志第 45 行），即更换预训练 Encoder 后直接用 UAD 全参数微调。 [实验支持] 早期 PCA≈0、GPD≈最大熵说明模态中心和原型几乎无区分；后续虽恢复，但 120 epoch 内未追上。**[机制假设]** 预训练特征与 UAD 头/预处理不匹配（而非单一超参）导致早期塌缩，需要加载权重逐层诊断。

**发现 10：训练配置本身足以产生大于多数模块改动的差异。**  [日志事实] H018 与 H014 同架构，仅把 DDP LR 从 0.032 降到 0.008，最终 8.35/23.14，相对 H014 为 −2.67/−6.57；这比 SCSR/KGL/PAT 等模块效应大得多。 [实验支持] 因此，小模块的 ±0.1–0.5 pp 差值不能轻易归因于机制；新增参数与统一 LR 的匹配度是必须控制的混杂因素。

## 8. 机制解释：哪些成立、哪些不成立

### 8.1 有日志/代码直接支持的机制

1. **训练-测试几何不一致（强）**：PAT 的 Part 目标只训练 Part Token/共享权重，测试只用 CLS；ViSA 的融合距离含 local 但融合 WRT detach global；TAUR 的排序 loss 只回 Adapter；KGL HNSM 的关系头不参与欧氏检索。这些不是猜测，是代码/日志可见的结构事实。它们与“mAP 升、R1 降/不升”的指标模式一致。
2. **新增参数/统一 LR 的优化不匹配（中强）**：TAUR 显式给 Adapter 3× LR，仍只产生 0.04%–1.6% 的排序梯度；H018 的 LR 对照显示 LR 可造成 −2.67/−6.57 的差异；SCSR/ICRE/PAT/KGL 的新模块均沿用 backbone LR。
3. **共同训练代价/优化干扰（中强）**：SFTC/ICRE 的 CE 在早期高于基线、指标差距中期扩大；RLE 四项损失全期偏高；HNSM 额外 loss 持续 ~0.6。这些支持“新增路径消耗共享容量/改变优化路径”，而不是“模块没执行”。
4. **阶段切换/预算不对等（强，针对 HiHR）**：Stage1 60 epoch + Stage2 60 epoch；同 Stage2 轮次的“早期领先”主要是预算；同总预算下 Stage2 切换造成 mAP/R1 双降，随后 mAP 恢复、R1 不恢复。
5. **早期塌缩（强，针对 M-SpecGene）**：PCA≈0、GPD≈ln500、CE≈ln500 是日志直接读数；与“初始化/预处理不匹配”一致。

### 8.2 日志不支持或无法确认的机制

- **后期过拟合**：没有看到“训练损失继续降、验证 mAP/R1 绝对下降”的组合；验证指标绝对斜率仍为正，且基线也在继续降损失、升指标。过拟合可能是相对饱和的一个成分，但**日志不能把它作为主因**。
- **原型库漂移/覆盖变化**：除 M-SpecGene 早期从最大熵恢复外，GPD loss 在所有实验中单调下降，没有中期尖峰/崩塌；M-SpecGene 是早期最大熵，不是后期漂移。没有读取 `PrototypeBank.prototypes`，无法计算 drift/coverage。**[机制假设，未验证]**
- **GPD 温度/EMA 滞后**：tau=0.03、momentum=0.2 固定（`UAD.yml:11-13`）；日志中没有温度/动量变化实验，也没有 GPD loss 异常。不能把后期落后归因于 EMA 滞后。**[机制假设，未验证]**
- **学习率与新增参数不匹配**：有 H018 和 TAUR 的 LR 证据，但没有每个模块的 LR sweep；不能量化“某一个模块”的 LR 失配。**[机制假设，部分支持]**
- **共同训练代价的具体来源**：SFTC 的 softmax 竞争、ICRE 的残差写回、RLE 的增强强度都只是结构性解释；没有 ON/OFF、梯度夹角或输入保真度统计。**[机制假设]**

### 8.3 对“后期持续下降”的直接回答

**日志事实是：没有持续下降。** 所有方法的 mAP/R1 绝对曲线在最后 30 epoch 仍上升，只是斜率小于基线；相对差距扩大主要发生在 R1。若可视化上看到“后期下降”，更可能是：(a) 与基线差距的曲线在下降；(b) 个别相邻验证点的波动（如 TAUR mAP 10.58→10.57、SCSR V3 R5 46.32→46.18）；(c) 把不同训练预算的 HiHR Stage2 曲线与 120 epoch 基线直接叠图。**这三类都不是模型在后期绝对退化。**

## 9. 证据边界与可复现性

- **日志镜像**：历史原始目录在本地不完整；本报告以 2026-10-24 审计镜像为准。镜像行号与 `02_Previous_Experiments.md` 的记录一致（如 H014 末次块 1121–1125、H001/H003 746–750）。本地 SCSR/SFTC/TAUR/ViSA 与镜像 md5 相同；H014 主日志与镜像 md5 相同。
- **验证集语义**：`Validation Results` 实际是测试集每 10 epoch 的评测；本文用它画轨迹，但正式结论仍取最后完整块，不按中间最优挑点。

- **单 seed/单次运行**：大多数 H 只有 seed1234 一次运行；ViSA 有 seed2025，但缺少匹配 seed 的 baseline，不能把 seed 差异当因果。
- **模式边界**：DDP 与 single 的 baseline 不同（H014 vs H019），不混用；HiHR Stage2 的预算修正只在 §4.3 使用。
- **未完成/无轨迹**：H004 只到 61 epoch、H027 无验证块、H048 只训练到 epoch 4 且无验证块（仅审计镜像有日志）；未纳入轨迹结论。
- **代码快照**：代码行号为本次静态读取的本地/镜像代码，历史训练时的代码版本未冻结；[实现事实] 只说明“当前读取到的实现”，不保证与训练时逐行一致。
